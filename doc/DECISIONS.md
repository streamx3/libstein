## D16 — Image encryption: ChaCha20-Poly1305 with LUKS2-style passphrase slots

**Decision.** Encrypted `.stein` images use AEAD_CHACHA20_POLY1305 (RFC 8439)
per chunk and for the manifest, one random master key per image wrapped in up
to eight passphrase slots (PBKDF2-HMAC-SHA256, 600 000 iterations by default;
the `kdf` field in the key area leaves room for Argon2id). The image hash is
keyed so it does not confirm known plaintext; keyless readers still verify
per-chunk CRCs. Own implementations in `stein_core`, cross-checked against
the Python `cryptography` package and the RFC 8439 vector.

**Why not AES-GCM.** ChaCha20-Poly1305 is fast in portable code on every CPU
libstein targets (no AES-NI dependency for Raspberry-Pi-class restore
sticks), is naturally constant-time, and is far smaller to implement and
review than AES + GHASH. AES-XTS (what LUKS uses for block devices) buys
nothing here: images are append-only chunk streams, so an AEAD with a
per-chunk nonce is the right tool. Pieces (`pt dump`, `fs dump`) will reuse
the same key-area format.
